## Prompt 1

> Let's come up with a plan for `rray_split(x, axes)`. This should allow you to split an array along a set of axes (which can't exceed the dimensionality of x), returning a list of arrays. I have a feeling we are going to need a new kind of iterator for this that operates blockwise. For example, splitting a 4x3x2 array along the 3rd axis would result in two 4x3x1 arrays, so we'd have to iterate over x in "blocks" to do this.

Researched the codebase and original rray implementation. Now entering plan mode.

## Plan

### Context

We need `rray_split()` to split an array along a set of axes, returning a list of subarrays. For example, splitting a 4x3x2 array along axis 3 yields two 4x3x1 arrays. The original rray (C++) used xtensor's strided views; we need a pure C implementation.

### Key insight: Two iterators, no new iterator type

The user's intuition about a "block iterator" is correct — we need to know two things for each input element:

1. **Which output subarray** it belongs to (list index)
2. **Where in that subarray** it goes (element position)

Both can be computed by the existing `rray_iterator` + `rray_reduction_iterator_init`, just with different `location_dimension_sizes`:

- **Element iterator**: `location_dimension_sizes` = input dims with split axes set to 1. This collapses the split axes, giving position within each subarray.
- **Split iterator**: `location_dimension_sizes` = input dims with non-split axes set to 1. This collapses everything except the split axes, giving the list index.

Both iterate the same `point_dimension_sizes` (input dims) and advance in lockstep.

#### Worked example: 4x3x2 split along axis 1

**Element iterator** (location dims = [1, 3, 2]):
- (0,0,0)→0, (1,0,0)→0, (2,0,0)→0, (3,0,0)→0, (0,1,0)→1, ...
- Groups of 4 map to same output position

**Split iterator** (location dims = [4, 1, 1]):
- (0,0,0)→0, (1,0,0)→1, (2,0,0)→2, (3,0,0)→3, (0,1,0)→0, ...
- Cycles through 4 list indices

### Algorithm in `split-template.h`

1. Extract x_dimension_sizes, dimensionality
2. Validate axes via arg_as_axes()
3. Compute out_dimension_sizes = x dims with split axes set to 1 (reuse rray_reduce_dimension_sizes)
4. Compute split_dimension_sizes = x dims with NON-split axes set to 1
5. n_splits = product of split axes sizes
6. out_capacity = product of out_dimension_sizes (capacity of each subarray)
7. Allocate output list of n_splits elements
8. Pre-allocate each subarray: r_alloc_vector(type, out_capacity), set dim attr
9. Initialize element_it (reduction iterator: input → element position)
10. Initialize split_it (reduction iterator: input → list index)
11. Loop i from 0 to x_capacity:
    - split_loc = split_it.location
    - element_loc = element_it.location
    - ASSIGN output_arrays[split_loc][element_loc] = x[i]
    - advance both iterators
12. Handle dimension names

### Dimension names

- **Non-split axes**: keep full dimension names from input
- **Split axes**: subset to 1 element based on which split

`rray_split_dimension_names()` iterates over splits, computing per-split multi-dimensional coordinates along split axes using modular arithmetic, then subsets names accordingly.

Both `rray_sum` and `rray_split` handle empty axes naturally:
- `rray_reduce_dimension_sizes()` with empty axes returns input dims unchanged
- For sum: output has same shape, each element gets `sum_one(0, x[i])` → copy
- For split: `n_splits = 1`, full capacity → `list(x)`
